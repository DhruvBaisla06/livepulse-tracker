1. Executive Summary & Abstract

LivePulse is an enterprise-grade, multi-tenant personal finance and expense analytics web application. Designed to bridge the divide between static spreadsheet software and disconnected expense trackers, LivePulse delivers an ultra-fast, visually engaging, and secure financial management experience.

Powered by React 19, Tailwind CSS v4, Supabase (PostgreSQL 15+), and Recharts 3, LivePulse provides bi-directional real-time ledger updates via WebSocket subscriptions without requiring manual page reloads. The platform features dynamic category budget caps with automated threshold defense, savings milestone planning, interactive multi-chart visualizations, and client-side audited Excel and CSV export engines.

2. Problem Statement & Motivation

❌ Traditional Spreadsheets (Excel / Sheets)

Steep learning curves, manual data entry, no automated mobile access, no threshold warnings before budgets are exceeded, and high risk of formula corruptions.

❌ Conventional Web Trackers

Require manual browser refreshes to recalculate balances, possess dull corporate interfaces, lack export capabilities, and have poor data isolation.

4.1 Multi-Persona Authentication System

  • Private Registered Account: Direct Supabase JWT authentication. Each user receives an isolated tenant schema with zero data crossover.
  • Demo Persona (demo@livepulse.app): Pre-loaded with 60 realistic transactions across 6 historical months (Arjun Mehta) for instant evaluation.
  • System Admin Persona (admin@livepulse.app): Populated with enterprise-scale corporate transactions (SaaS retainers, cloud infrastructure clusters, leases).

4.2 Real-Time Executive Dashboard

  • KPI Stat Cards: Real-time calculations for Total Income, Total Expenses, Net Savings, and Budget Remaining with trend indicators.
  • Interactive Chart Suite: 6-month historical Area trend curves, side-by-side comparative Bar charts, and Category donut breakdown.
  • Recent Activity Feed: Latest 8 transactions with category tags, relative timestamps, and color-coded values.

4.3 Full CRUD Transaction Ledger

  • Live filtering by transaction type (All / Income / Expense), category taxonomy, and search text.
  • In-place modal editing with reactive recalculation across the entire application.
  • Double-confirmation delete safety modal to prevent accidental financial ledger destruction.

4.4 Category Budgeting & Threshold Defense Guard

  • Category-specific monthly expenditure caps.
  • Dynamic automated status badges:
    • Healthy (Green): Spending < 80% of category limit.
    • Warning (Amber): Spending between 80% and 100% of category limit.
    • Exceeded (Red): Spending > 100% of allocated limit.

4.5 Savings Goals Milestone Engine

  • Target milestone cards with target amounts, saved balances, and target deadlines.

4.6 Audited Financial Statements & Reports

  • Monthly and annual statement summaries with cash retention percentages.

5. Database Schema & Data Models

LivePulse utilizes 6 primary relational tables structured under PostgreSQL with strict foreign keys, check constraints, and performance indexes:

Table Name Primary Key Foreign Keys Purpose & Stored Attributes
profiles id UUID auth.users(id) User identity, full name, email, avatar URL, currency (INR), date format preferences.
categories id UUID user_id -> auth.users Custom categories, transaction type ('income'|'expense'), icon, color accent.
transactions id UUID user_id -> auth.users Financial records: type, category, amount, description, date, payment account.
budgets id UUID user_id -> auth.users Monthly budget caps per category, spending limits, period definitions.
savings_goals id UUID user_id -> auth.users Target goals, target amount, current saved amount, icon, deadline date.
notifications id UUID user_id -> auth.users Real-time alert logs: type ('info'|'warning'|'success'|'error'), title, message, read flag.

6. Security & Data Protection Framework

🔒 PostgreSQL Row Level Security (RLS) Implementation

Security is enforced directly at the database engine level. Every table enables RLS policies requiring that queries match the cryptographically verified JWT identity: 

ALTER TABLE transactions ENABLE ROW LEVEL SECURITY;

CREATE POLICY "Users can CRUD own transactions" ON transactions
  FOR ALL USING (auth.uid() = user_id)
  WITH CHECK (auth.uid() = user_id);

Key Security Highlights:

  • Kernel-Level Isolation: Even if a malicious request attempts to query another tenant's records, PostgreSQL drops the query at the kernel level with zero rows returned.
  • Zero Secret Key Leakage: Only the public VITE_SUPABASE_ANON_KEY is embedded in frontend assets. The master service_role key is never exposed.
  • Channel Authorization: Realtime WebSocket channels are filtered explicitly by user_id=eq.${user.id}.

8. Presentation Talking Points & Q&A Defense

Q1: How does LivePulse recalculate dashboard totals without page reloads?

Answer: Through a global React Context (TransactionProvider) coupled with Supabase Realtime WebSocket subscriptions. When a transaction is committed, the optimistic state updates immediately in memory, and the WebSocket payload synchronizes all open browser tabs and devices in real time.

Q2: What prevents unauthorized access between different users?

Answer: PostgreSQL Row Level Security (RLS) policies. Rather than relying solely on frontend checks, the database engine verifies that the authenticated user's token UUID matches the row's user_id before executing any SELECT, INSERT, UPDATE, or DELETE operation.

Q3: Why was Recharts selected over Chart.js or Canvas?

Answer: Recharts is built natively with React components and SVG. It provides declarative JSX syntax, effortless responsive scaling via <ResponsiveContainer>, and avoids Canvas pixelation on high-DPI screens.
